# todolist

A collaborative todo app: multi-list, assignment, 3-level sharing, accomplishment
history, in-app and email notifications, and natural-language capture backed by a
Databricks Model Serving endpoint.

## This repo is a module, not an app

It has no `package.json`, no build config, and no deploy config. It is mounted at
`/todolist` by the **`home`** shell app, which owns the dependencies, the build,
and the Databricks App deployment. Clone `home` and work there — this repo lives
at `apps/todolist` inside it as a git submodule.

- `server/` — Express routes registered through `appkit.server.extend`, plus the
  Postgres schema (`todolist`), email sending, background jobs, and AI capture.
  Entry point: `setupTodolistRoutes(appkit, { distPath })`.
- `client/` — React SPA built with Vite `base: '/todolist/'` and a React Router
  `basename` of `/todolist`.

The shell passes `distPath` in, so this module never assumes where it sits on
disk. The `/todolist` URL prefix, however, is baked into the routes, the Vite
base, the router basename, and `client/public/manifest.webmanifest`.

## Changing something here

Commit and push in this repo first, then commit the updated submodule pointer in
`home`. Build and test from `home` (`npm run build:todolist`, `npm run dev`).

## Why the manifest icons point at catbox.moe

An experiment, and a reversible one. Installing this app on Android never
produced a real PWA — only a browser shortcut — while desktop Chrome installed
it fine and the manifest, icons and service worker all validated. The cause is
that Android builds a WebAPK through Google's minting service, which fetches
the manifest and icons **from its own servers**. Everything here sits behind the
Databricks OAuth proxy, so those fetches get a login page and minting fails;
Chrome then falls back to a shortcut. A public PWA (excalidraw) installs on the
same phone, which isolates the cause to our auth gate.

Manifest icons are allowed to be cross-origin, so the four PNGs are also hosted
publicly to see whether icon fetching is the specific blocker. The originals
stay in `client/public/icons/` and are still served and precached — they are the
source of truth, regenerated by `scripts/generate-todolist-icons.mjs` in `home`.

If this did not fix the Android install, revert the `src` values to the local
`/todolist/icons/*` paths; nothing else depends on the public copies. If it did,
move them somewhere durable that we control rather than leaving a personal app
depending on an anonymous file host.
