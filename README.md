# todolist

A collaborative todo app: multi-list, assignment, 3-level sharing, accomplishment
history, in-app and email notifications, and natural-language capture backed by a
Databricks Model Serving endpoint.

## This repo is a module, not an app

It has no `package.json`, no build config, and no deploy config. It is mounted at
`/todolist` by the **`home`** shell app, which owns the dependencies, the build,
and the Databricks App deployment. Clone `home` and work there — this repo lives
at `apps/todolist` inside it as a git submodule.

- `server/` — Express routes registered through `appkit.server.extend`, plus the
  Postgres schema (`todolist`), email sending, background jobs, and AI capture.
  Entry point: `setupTodolistRoutes(appkit, { distPath })`.
- `client/` — React SPA built with Vite `base: '/todolist/'` and a React Router
  `basename` of `/todolist`.

The shell passes `distPath` in, so this module never assumes where it sits on
disk. The `/todolist` URL prefix, however, is baked into the routes, the Vite
base, the router basename, and `client/public/manifest.webmanifest`.

## Changing something here

Commit and push in this repo first, then commit the updated submodule pointer in
`home`. Build and test from `home` (`npm run build:todolist`, `npm run dev`).

## Why the manifest icons are hosted off-site

Installing this app on Android never produced a real PWA — only a browser
shortcut — while desktop Chrome installed it fine and the manifest, icons and
service worker all validated. The cause: Android builds a WebAPK through
Google's minting service, which downloads the **icons from its own servers**.
Everything here sits behind the Databricks OAuth proxy, so those fetches got a
login page and minting failed; Chrome then silently falls back to a shortcut. A
public PWA (excalidraw) installed on the same phone, which isolated the cause to
our auth gate. Publishing the icons fixed it immediately.

Only the icons need this. The manifest itself does not — Chrome parses it in the
browser (with the user's session, hence `crossorigin="use-credentials"` on the
link tag) and sends its contents to the minting service directly. Screenshots do
not either: they are rendered into the install dialog by the browser on the
device, which is authenticated.

The originals stay in `client/public/icons/` and are still served and precached —
they are the source of truth, regenerated by `scripts/generate-todolist-icons.mjs`
in `home`. The public copies must simply be byte-identical and reachable.

⚠ These URLs must keep working for as long as the app is installed, not just at
first install: Chrome re-reads the manifest roughly daily and re-mints the
WebAPK when it changes, re-fetching the icons each time. A dead URL means a
broken launcher icon weeks later, with nothing to connect it to the cause.
They are served from `alexalot.com`, a Cloudflare Worker holding nothing but
these four files. Re-upload them there whenever the generator is re-run — the
manifest points at those copies, and nothing enforces that the two stay in sync.
